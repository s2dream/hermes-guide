LobeHub 연결하기

구 LobeChat의 현재 프로젝트인 LobeHub에서 OpenAI 호환 제공자를 Hermes로 설정합니다.

자료 확인: 2026.10.24 · 비공식 한국어 가이드 · 실제 계정 연결 및 설치 실기 검증은 포함하지 않습니다.

이 페이지에서

1. 공통 준비와 설치 범위2. 공식 Compose로 LobeHub 설치하기3. Hermes 주소와 사용자 지정 모델 등록4. 실행하고 모델 선택하기문제 해결과 원격 접속공식 자료와 연결 범위

명령은 내 Ubuntu 터미널에서 실행하세요. 이 가이드는 키를 입력받지 않습니다.

1. 공통 준비와 설치 범위

먼저 공통 준비부터 API 확인까지 완료하세요. 같은 Ubuntu의 Docker Engine, 브리지 주소에 바인딩한 Hermes API, API 접속 비밀키와 실제 모델 ID가 필요합니다.

현재 공식 저장소와 이미지는 lobehub/lobehub입니다. 최신 서버 버전에는 PostgreSQL·오브젝트 저장소·인증 등 여러 구성 요소가 필요하므로, 과거의 단일 lobehub/lobe-chat 실행 예시와 섞지 마세요.

2. 공식 Compose로 LobeHub 설치하기

새 설치용 디렉터리를 만들고 공식 Docker Compose 가이드의 초기 설정을 따릅니다. 아래는 설정 스크립트를 먼저 내려받아 확인하는 방식입니다. 기존 운영 설치에서는 초기 설정을 다시 실행하지 마세요.

Ubuntu 터미널 · Bash
mkdir -p ~/hermes-uis/lobehub
cd ~/hermes-uis/lobehub
umask 077
curl -fsSL https://lobe.li/setup.sh -o setup.sh
less setup.sh
bash setup.sh -l en

Local Mode로 구성하고 생성된 접속 주소·키를 보관합니다. Docker 실행 질문이 나오면 먼저 다음 단계의 Hermes 연결 설정을 마친 뒤 시작하세요. 이 설치는 여러 이미지 다운로드와 디스크 공간이 필요합니다.

포트와 기존 설치를 확인하세요.

현재 공식 Compose에는 3210, 9000, 9001, 8787, 8788 등의 서비스가 있습니다. 최초 시작 전에 Compose의 공개 포트를 확인하고 로컬용 포트는 127.0.0.1:호스트포트:컨테이너포트로 제한하세요. DB·Redis에 외부 접속이 필요 없다면 해당 ports 항목을 제거할 수 있습니다.

3. Hermes 주소와 사용자 지정 모델 등록

생성된 LobeHub의 .env를 열어 기존 DB·인증·저장소 설정을 유지하고 아래 값을 추가·수정합니다.

.env · 기존 설정에 추가
OPENAI_API_KEY=REPLACE_WITH_HERMES_API_KEY
OPENAI_PROXY_URL=http://host.docker.internal:8642/v1
OPENAI_MODEL_LIST=-all,+hermes-agent
SSRF_ALLOW_IP_ADDRESS_LIST=REPLACE_WITH_DOCKER_BRIDGE_IP

API 키와 실제 모델 ID를 바꿉니다. REPLACE_WITH_DOCKER_BRIDGE_IP에는 공통 Docker 준비에서 확인한 172.17.0.1 같은 실제 주소를 넣으세요. 기존 허용 IP 목록이 있으면 쉼표로 추가합니다. 사설 IP 차단을 전체 해제하는 대신 해당 주소만 허용합니다.

같은 디렉터리의 docker-compose.override.yml에 아래 호스트 매핑을 추가합니다. 공식 Compose 서비스 이름은 lobe입니다. 이미 override 파일이 있으면 기존 내용을 유지하고 이 설정을 병합하세요.

docker-compose.override.yml
services:
  lobe:
    extra_hosts:
      - "host.docker.internal:host-gateway"
환경 파일이 컨테이너로 전달되는지 확인하세요.

현재 공식 Compose의 lobe 서비스는 env_file: .env를 사용합니다. 다른 템플릿에서는 해당 환경변수를 서비스에 직접 전달해야 할 수 있습니다. 단순한 YAML 치환용 .env만으로는 컨테이너에 자동 주입되지 않습니다.

4. 실행하고 모델 선택하기

Ubuntu 터미널 · Bash
docker compose up -d
docker compose ps
docker compose logs --tail 80 lobe
  1. http://localhost:3210을 열고 공식 설치 과정에서 구성한 인증 방식으로 로그인합니다.
  2. App Settings → AI Providers → OpenAI에서 제공자를 켭니다. 필요하면 주소와 Hermes API 접속 키를 입력합니다.
  3. 사용자 지정 모델 ID hermes-agent 또는 실제 /v1/models 결과를 추가·활성화하고 Agent 설정에서 선택합니다.
  4. 기본 텍스트 대화로 아래 문장을 보내 확인합니다. 연결 확인 기능이 다른 기본 모델을 시험하면, 실제 Hermes 모델을 선택한 대화 결과로 판단하세요.
안녕! 한국어로 답해 줘. 파일을 바꾸거나 명령을 실행하지 말고, 네가 도와줄 수 있는 일을 간단히 설명해 줘.

Hermes의 도구는 API 서버가 처리합니다. LobeHub 자체 플러그인·도구·에이전트 게이트웨이는 별도 기능이므로, 처음 연결할 때는 추가 도구를 켜지 않은 텍스트 대화부터 확인하세요.

문제 해결과 원격 접속

증상확인할 내용
SSRF / private IP 차단실제 Docker 브리지 IP를 SSRF_ALLOW_IP_ADDRESS_LIST에 넣고 lobe 컨테이너를 재생성합니다.
host.docker.internal을 찾지 못해요extra_hosts가 실제 lobe 서비스에 적용되었는지 확인합니다.
모델이 없거나 지원되지 않아요OPENAI_MODEL_LIST와 실제 Hermes 모델 ID를 맞추고 Agent에서도 해당 모델을 선택합니다.
로그인·DB·업로드 오류LobeHub 설치 구성 문제부터 공식 Compose 문서로 확인합니다. Hermes의 API 인증과는 별도입니다.

원격 Ubuntu는 SSH로 UI 포트 3210을 전달하세요. 현재 LobeHub의 Gateway Mode나 업로드도 사용하려면 Local Mode가 출력한 추가 서비스 주소에 맞춰 8787, 9000 등을 전달해야 할 수 있습니다. 공개 서비스가 필요하면 공식 Domain Mode의 인증·HTTPS 설정을 따르세요.

Ubuntu 터미널 · Bash
ssh -N \
  -L 3210:127.0.0.1:3210 \
  -L 8787:127.0.0.1:8787 \
  -L 9000:127.0.0.1:9000 \
  USER@SERVER

종료는 설치 디렉터리에서 docker compose stop, 재시작은 docker compose start입니다. DB와 업로드 데이터는 보존하세요.

  • 공식 Compose 설치
  • 모델 제공자 환경변수
  • OpenAI 제공자 화면 설정
  • 사설 IP 허용 목록 설정 예시

공식 설정 기능을 조합한 연결 안내이며 실제 설치·로그인 조합은 검증하지 않았습니다. NextChat·LobeHub는 Open WebUI처럼 Hermes 전용 연결 문서가 있는 경우와 구분해 보세요.
