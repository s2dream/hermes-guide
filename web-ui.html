어떤 웹 UI를 연결할 수 있나요?

Hermes는 OpenAI 호환 API 서버를 제공합니다. Open WebUI, NextChat, LobeHub, LibreChat 같은 UI가 이 API로 메시지를 전달하면, 도구와 파일 작업은 Hermes가 실행되는 Ubuntu에서 처리됩니다.

프로젝트GitHub 별특징·연결 방식안내

인기도 기준: 비교한 후보 중 GitHub 누적 별 수 상위 3개를 선정했습니다. 별 수는 프로젝트 전체 관심도의 대리 지표이며, 실제 사용자 수나 Hermes 연동 점유율 순위는 아닙니다. 데스크톱 전용 앱은 비교 대상에서 제외했습니다.

별 수는 GitHub 공개 API의 stargazers_count로 조회했습니다. 각 프로젝트 이름은 해당 저장소로 연결되며, 수치는 이후 달라질 수 있습니다.

추가 설치 없이 관리 화면부터 보고 싶다면

Hermes에는 별도 제품 설치 없이 여는 내장 대시보드도 있습니다. 설정·세션 관리가 목적이면 먼저 이 기능을 살펴보세요. 비교표의 커뮤니티 Hermes WebUI와는 다른 기능입니다.

Ubuntu 터미널 · Bash
hermes dashboard

기본 주소는 http://127.0.0.1:9119입니다. 브라우저 Chat 탭은 지원 버전에서 hermes dashboard --tui로 켭니다. 선택 의존성이 없으면 출력되는 설치 안내를 따르세요.

공통 준비: Ubuntu와 Docker

설치·모델 연결를 마치고 Hermes가 답변하는지 먼저 확인합니다. 세 연동 안내는 Hermes와 Docker Engine이 같은 Ubuntu 호스트에 있는 구성을 기준으로 합니다.

Docker가 없다면 Docker 공식 Ubuntu 설치 안내를 먼저 따르세요. LobeHub는 Docker Compose 플러그인도 필요합니다.

Ubuntu 터미널 · Bash
docker --version
docker compose version
웹 UI의 기능과 Hermes 도구는 별개입니다.

기본 텍스트 대화 연결부터 확인하세요. UI의 자체 검색·도구 호출·이미지 생성·지식베이스가 모두 Hermes API에 대응하는 것은 아닙니다.

1. Hermes API와 비밀키 설정

Ubuntu 터미널 · Bash
openssl rand -hex 32

출력된 임의 문자열을 API 전용 비밀키로 사용합니다. ~/.hermes/.env를 열고 기존 내용은 유지하면서 아래 항목을 추가·수정하세요. REPLACE_WITH_RANDOM_SECRET는 방금 생성한 문자열로 바꿉니다.

~/.hermes/.env · 기존 내용 유지
API_SERVER_ENABLED=true
API_SERVER_KEY=REPLACE_WITH_RANDOM_SECRET
API_SERVER_HOST=127.0.0.1
API_SERVER_PORT=8642
여기의 API 키는 Hermes 접속용입니다.

Open WebUI 등의 OPENAI_API_KEY 필드에도 이 키를 넣습니다. 모델 제공자의 API 키나 ChatGPT 로그인 토큰을 UI에 다시 넣는 절차가 아닙니다.

2. Docker에서 호스트의 Hermes에 연결하기

Docker 컨테이너의 127.0.0.1은 컨테이너 자신을 뜻합니다. 따라서 Hermes가 루프백에만 바인딩되어 있으면 호스트 이름을 추가하는 것만으로 연결되지 않습니다.

아래 명령으로 Docker 기본 브리지의 게이트웨이 주소를 확인합니다. Docker가 실행 중인 Ubuntu 터미널에서 수행하세요.

Ubuntu 터미널 · Bash
HERMES_DOCKER_HOST=$(docker network inspect bridge --format '{{(index .IPAM.Config 0).Gateway}}')
printf 'Hermes API bind address: %s\n' "$HERMES_DOCKER_HOST"

출력 예시는 172.17.0.1이며 실제 값은 환경마다 다릅니다. ~/.hermes/.env의 API_SERVER_HOST=127.0.0.1을 API_SERVER_HOST=실제로_출력된_IP로 수정하세요. Hermes는 이 브리지 주소에서만 수신합니다. 비어 있거나 Docker 오류가 나오면 먼저 Docker를 점검하세요. API 키와 포트 설정은 앞 단계 값을 유지합니다.

각 UI 컨테이너에는 host.docker.internal:host-gateway 매핑을 추가합니다. UI의 연결 주소는 http://host.docker.internal:8642/v1입니다. API_SERVER_HOST=0.0.0.0으로 바꿀 필요가 없습니다.

이미 다른 UI가 Hermes를 사용 중이라면

API 수신 주소를 바꾸면 기존 127.0.0.1:8642 연결도 새 브리지 주소로 바꿔야 합니다. Docker 없이 사용하던 구성으로 돌아가려면 같은 파일의 값을 API_SERVER_HOST=127.0.0.1로 복원한 뒤 게이트웨이를 재시작하세요.

3. 게이트웨이를 시작하고 API 확인

Ubuntu 터미널 · Bash
hermes gateway

기존 게이트웨이가 있으면 기존 프로세스를 먼저 종료하고 한 번만 실행합니다. 텔레그램을 연결한 게이트웨이도 동일한 프로세스에서 API를 제공할 수 있습니다.

게이트웨이 터미널은 열어 두고, 새 Ubuntu 터미널에서 다음 명령을 실행합니다. 비밀키 입력은 화면에 표시되지 않으며 셸 기록에 실제 키를 적지 않습니다.

Ubuntu 터미널 · Bash
HERMES_DOCKER_HOST=$(docker network inspect bridge --format '{{(index .IPAM.Config 0).Gateway}}')
curl --fail --silent --show-error "http://$HERMES_DOCKER_HOST:8642/health"
read -rsp "Hermes API key: " HERMES_API_KEY; printf '\n'
curl --fail --silent --show-error \
  -H "Authorization: Bearer $HERMES_API_KEY" \
  "http://$HERMES_DOCKER_HOST:8642/v1/models"
unset HERMES_API_KEY

/health의 상태와 /v1/models의 모델 목록을 확인합니다. 기본 프로필의 모델 ID는 hermes-agent이며 프로필·설정에 따라 다를 수 있습니다. 아래 제품별 안내에서는 실제 목록에 나온 ID를 사용하세요.

Open WebUI 연결 안내대화·사용자 관리가 필요한 경우NextChat 연결 안내개인 채팅 화면으로 시작하는 경우LobeHub 연결 안내에이전트별 설정을 함께 관리하는 경우

원격 Ubuntu에서 실행한다면

브라우저는 UI 포트로 접속하고, Hermes API는 Ubuntu 내부 연결로 둡니다. 로컬 컴퓨터의 터미널에서 필요한 UI 포트만 SSH로 전달하세요.

Ubuntu 터미널 · Bash
ssh -N -L 3000:127.0.0.1:3000 USER@SERVER

이후 내 브라우저에서 http://localhost:3000을 엽니다. USER@SERVER를 내 서버 정보로 바꾸세요. NextChat는 3001, LobeHub는 3210으로 양쪽 포트를 바꿉니다. LobeHub의 추가 서비스는 해당 페이지의 원격 접속 안내도 확인하세요.
